# SEO Audit & Optimization Plan — Upwork Text Formatter

2026-08-24 (revised) · Search & Discoverability score: 32/100 · Basis: full source read of the current Next.js 15 App Router codebase — every page/component, `next.config.ts`, `package.json`, `plan.md`, and `CLAUDE.md` — pulled fresh from the project folder. Live rendering, PageSpeed/Core Web Vitals, HTTP response headers, and Search Console/backlink data were not accessible this session — see "What I couldn't determine."

This revision expands the original audit into the three standard SEO categories — **on-page, technical, and off-page** — and adds several findings the first pass didn't cover: a content-accuracy bug on the legal pages, a stray outbound link, and a note on a divergence I found between what this audit was written against and other recent edits to the same files. Nothing here has been implemented — this file only documents findings and recommendations.

## The one thing

This tool has almost nothing wrong with what it *says* — the copy, the single H1, the heading hierarchy, the meta description are all fine. What it's missing is everything that lets Google *find, trust, and display* what it says: there is no `robots.txt`, no sitemap, no canonical URL, no Open Graph/Twitter cards, and no structured data anywhere in the codebase — not even for the FAQ section, which is sitting there fully written and crawlable, one script tag away from FAQ rich results. Off-page, the picture is the same story at a different layer: zero backlink surface, zero directory presence, zero distribution channel besides word of mouth. Right now this reads less like a site with SEO problems and more like a site SEO hasn't been switched on for yet. That's actually the good news: the fixes below are almost entirely additive (new files, new metadata objects, new outreach), not rewrites.

## On-page SEO: fixes

**1. Ship a complete Metadata API config in `layout.tsx`.** Effort: S · Confidence: High
Replace the current bare-bones `metadata` export with a full object: `metadataBase` (needed once a production domain is live), a `title.template` (`"%s | Upwork Text Formatter"`) so `/privacy` and `/terms` stop hand-rolling the same suffix, `alternates.canonical`, `robots: { index: true, follow: true }`, `openGraph` (title/description/url/siteName/images/locale/type), and `twitter` (`card: 'summary_large_image'`). Skip the `keywords` field, or add it only as an afterthought — Google has ignored the meta-keywords tag for ranking purposes for years; it's not harmful to include, just don't expect it to do anything.

**2. Fix the "Last updated" date on `/privacy` and `/terms`.** Effort: S · Confidence: High
`Last updated: {new Date().toLocaleDateString()}` renders the *current* date on every request (or the build date, frozen forever, if the page is statically generated) — neither is the actual date the policy content last changed. This is a real accuracy problem, not just cosmetic: dynamically-"fresh" legal pages that never actually change read as untrustworthy to both users and Google's quality signals for policy content. Replace with a hardcoded date string that's updated by hand whenever the copy actually changes.

**3. Reconsider the `buraq.dev` outbound links.** Effort: S · Confidence: Medium
The footer's "Contact us" and the waitlist section's "Join Us" both send visitors (and any link equity) to a third-party domain instead of a contact channel on the product's own domain. If `buraq.dev` is the agency/developer's own site, that's a legitimate choice, but it's worth being deliberate about — consider a `mailto:` link to `hello@upworkformatter.com` (already used elsewhere in the codebase) or a same-domain contact page instead, so outbound trust and internal link equity aren't leaking to an unrelated brand on your two highest-visibility CTAs.

**4. Widen keyword coverage in existing copy.** Effort: M · Confidence: Medium
The current copy nails the branded query but doesn't work in the phrasing people actually type when they don't know this tool exists yet: "upwork proposal formatting," "bold text generator for upwork," "upwork message formatting stripped," "unicode bold text." A light pass over the Hero subtext, `WhyFormat` card copy, and FAQ answers to naturally include a few of these (no keyword-stuffing needed — the FAQ answers already come close) would broaden what this page can rank for without adding new pages.

**5. Build content depth beyond the single page.** Effort: L · Confidence: High
This is a well-executed one-pager, but one page can only rank for so many query variants. The FAQ answers already contain the seeds of standalone articles ("why Upwork strips formatting," "why underline renders differently," "does Ctrl+Z break after pasting"). A handful of short `/guides` or `/blog` pages targeting long-tail, non-branded queries would let this compete for search volume well beyond people who already know the tool's name. Right now every ranking opportunity is branded-search-only.

**6. Add light E-E-A-T signals.** Effort: S/M · Confidence: Medium
Not urgent for a free, non-YMYL utility, but a short "About"/"Who built this" note, a real support contact on the product's own domain, and (once there's usage) a simple "used by N freelancers" or similar social-proof line would all help both user trust and the kind of signals Google's quality systems look for on a page asking to be trusted with pasted proposal text.

## Technical SEO: fixes

**7. Add `app/robots.ts` and `app/sitemap.ts`.** Effort: S · Confidence: High
Next.js 15 generates both from a typed route file — no manual XML. `sitemap.ts` should list `/`, `/privacy`, `/terms` with `lastModified`/`changeFrequency`/`priority`; `robots.ts` should allow all crawlers and point `sitemap` at the generated URL. Without this, there's no signal telling Google what exists on the site or that it's allowed to be indexed at all — this is the most basic fix and it's currently a zero.

**8. Add `FAQPage` and `SoftwareApplication` JSON-LD.** Effort: S · Confidence: High
The `FAQS` array in `Faq.tsx` is already exactly the shape schema.org wants — map it directly into a `FAQPage` script tag rendered on the homepage (question/answer pairs, no rewriting needed). Add a `SoftwareApplication` block too: `applicationCategory: "BusinessApplication"`, `operatingSystem: "Any (Web)"`, `offers: { price: "0", priceCurrency: "USD" }`. Do **not** add fake `aggregateRating`/review schema with no real reviews behind it — Google actively penalizes fabricated review markup. Combined (real data only), these are what make Google eligible to show a FAQ accordion directly in the SERP — free visibility gain with content already written.

**9. Add an Open Graph image.** Effort: S/M · Confidence: High
Next.js supports a file-convention `opengraph-image.tsx` (renders a 1200×630 image via `ImageResponse` — no design tool needed, can reuse the brand green and the logo mark). Every link shared into a freelancer Slack/Discord/subreddit currently shows as a bare gray link card. This is a conversion-on-share problem as much as an SEO one.

**10. Switch the retired `/editor` route to `permanentRedirect()`.** Effort: S · Confidence: High
`app/editor/page.tsx` currently uses `redirect('/#editor')`, which issues a **temporary (307)** redirect by Next.js's default. If `/editor` was ever indexed or linked to (old bookmarks, backlinks), a temporary redirect tells search engines the move might not be permanent, so link equity and indexing don't fully consolidate onto `/`. Switch to `permanentRedirect()` for a 308.

**11. Full favicon/manifest set.** Effort: S · Confidence: High
Add `apple-touch-icon.png`, PWA-style icons, and a `manifest.json` (or `icon.tsx`/`apple-icon.tsx` file conventions). Affects how the site's icon renders in Google's mobile SERP and in browser tabs/bookmarks — minor but real trust signals.

**12. Preconnect the Material Symbols stylesheet.** Effort: S · Confidence: High
Add `<link rel="preconnect" href="https://fonts.googleapis.com" />` and `<link rel="preconnect" href="https://fonts.gstatic.com" crossOrigin="anonymous" />` above the existing stylesheet link, or consider inlining the handful of icons actually used as SVGs to drop the external request entirely. Poppins already gets the correct self-hosted treatment via `next/font` — the icon font is the one exception.

**13. Reconsider `PageLoader.tsx`'s fixed delay.** Effort: S · Confidence: Medium
It shows a full-viewport, `aria-hidden` splash screen for a hardcoded minimum ~500–800ms on every first load, regardless of whether the page is actually ready — there's nothing being fetched to justify gating on it. This isn't a classic on-page issue, but it's a self-inflicted perceived-performance cost that risks the loader's own text becoming the measured Largest Contentful Paint element instead of the real hero content, and it depends on the same render-blocking icon font flagged in #12. Worth removing or shortening once real Core Web Vitals are measurable (see gaps below).

**14. Add baseline security/response headers.** Effort: S · Confidence: Medium
`next.config.ts` currently has no `headers()` configuration at all. Once a host is chosen, add at minimum `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, and `Referrer-Policy`. Not classic keyword-and-ranking SEO, but part of Google's page-experience signals and a basic trust hygiene item.

**15. Clean up unused starter assets.** Effort: XS · Confidence: High
`public/file.svg`, `globe.svg`, `next.svg`, `vercel.svg`, and `window.svg` (the default `create-next-app` scaffolding) don't appear referenced anywhere in `src/`. No SEO impact either way, but worth clearing out as part of a launch-readiness pass.

## Off-page SEO: strategy

**16. Verify production domain + Search Console + Bing Webmaster Tools.** Effort: S · Confidence: High
The privacy/terms pages reference `hello@upworkformatter.com`, suggesting a target domain, but live deployment status couldn't be confirmed this session. Once a domain is locked, `metadataBase` in fix #1 depends on it, and the site should be verified in both Google Search Console and Bing Webmaster Tools with the sitemap from fix #7 submitted — none of the on-page or technical work matters until Google is actually told the site exists.

**17. Directory and citation building.** Effort: M · Confidence: Medium
Cheap, fast wins once the domain is live: a Product Hunt launch, BetaList, listings on freelancer-tool roundup sites and AlternativeTo-style directories, and a presence on Indie Hackers. Each is a legitimate, low-effort backlink plus a distribution channel to actual freelancers.

**18. Community engagement, done as participation, not link-dropping.** Effort: M (ongoing) · Confidence: Medium
Answering relevant threads on r/Upwork, r/freelance, r/forhire, and the Upwork community forums — where this tool's exact use case gets discussed — with a link back works, but only as genuine participation; drive-by link-dropping gets posts removed and can get accounts banned on most of these communities. Treat this as an ongoing relationship, not a one-time backlink tactic.

**19. Turn the Unicode-trick explanation into a distribution asset.** Effort: M · Confidence: Medium
"Why Upwork strips formatting, and how Unicode substitution gets around it" is a genuinely interesting technical story that's currently buried in one FAQ answer. It's a natural fit for a short guest post or article on dev.to/Hashnode, or a pitch to freelancer-focused newsletters — content that attracts organic backlinks from a technical audience while also functioning as top-of-funnel awareness for non-branded searchers.

**20. Competitor backlink research, once tooling is available.** Effort: M · Confidence: Low (dependent on tool access)
Once a tool like Ahrefs, Semrush, or even the free tier of Ubersuggest is available, check what similar tools (e.g. the reference product this project was originally modeled on) are listed on or linked from — often the fastest way to find directories and roundup posts worth targeting.

## One flag before you invest heavily here

The product is named "Upwork Text Formatter," the brand-green accent color deliberately echoes Upwork's own (confirmed directly in `globals.css`'s comments and in `CLAUDE.md`), and the target domain looks like `upworkformatter.com`. Using another company's trademark as the literal product name and (apparently) as part of the domain is a real risk with a marketplace as active about brand enforcement as Upwork — a takedown or forced rebrand later would forfeit every backlink, every ranking, and every bit of domain authority built with the plan above. I did not find a confirmed, current Upwork trademark/brand-use policy to check this against — I'd treat this as a "verify before you scale spend on this domain" item, not a "definitely a problem" one. Worth a few minutes with a lawyer or at minimum Upwork's published legal/brand pages before putting real budget behind content and backlinks.

Sources checked (not conclusive — recommend direct verification): [Upwork Legal Center](https://www.upwork.com/legal)

## A note on codebase drift

The files this audit was verified against show signs of two different edit histories layered on top of each other: `NavBar.tsx`, `Toolbar.tsx`, `Logo.tsx`, and `Faq.tsx` use one design-token system (`bg-brand`, `text-on-surface`, etc.), while `Hero.tsx`, `FormatterApp.tsx`, `Footer.tsx`, `page.tsx`, and the newer `/privacy`, `/terms`, `WaitlistSection.tsx`, and `not-found.tsx` files use raw Tailwind slate/blue utility classes and a different footer/content direction (buraq.dev links, "Have something in mind? Let's connect.") than what's documented elsewhere as the current design. This doesn't change any of the SEO findings above — the missing sitemap, structured data, etc. are missing either way — but it's worth reconciling which version of the design is actually current before spending effort on content work that assumes one or the other, since a couple of the fixes above (the OG image's colors, the metadata title/description wording) are cosmetic enough to be affected by which direction wins.

## What's already working

- **Intent match is exactly right.** The homepage doesn't send transactional searchers to a marketing page that makes them click again — the tool is embedded directly above the fold. That's the correct structure and it's rarer than it should be.
- **Poppins is self-hosted via `next/font`**, avoiding the classic external-font-blocking penalty — the codebase clearly already knows this pattern, it just wasn't extended to the Material Symbols icon font.
- **The FAQ content is genuinely good and already crawlable** — real answers to real objections, rendered as server-side HTML in native `<details>/<summary>` elements rather than hidden behind client-side JS. It's 90% of the way to a strong `FAQPage` rich result already; the missing 10% is just the JSON-LD wrapper (fix #8).
- **Heading hierarchy is clean throughout** — one H1 per page, sensibly nested H2s/H3s, no headings borrowed for visual styling. A lot of sites this kind of audit sees get this wrong; this one didn't.
- **Custom 404 handling is correct** — `not-found.tsx` exists and is served properly for unmatched routes, avoiding the soft-404 trap some sites fall into.
- **`lang="en"` and a correct default viewport meta are both present**, courtesy of the App Router's defaults — no action needed on either.
